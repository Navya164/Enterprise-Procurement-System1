🏢 Smart Procurement & Purchase Order Management System

**Project Overview**

The Enterprise Procurement & Purchase Order Management System is a role-based web application designed to digitize and streamline the complete procurement process within an organization.

Traditional procurement often involves manual requests, email-based approvals, delayed decision-making, and limited visibility into purchase status. This system brings the entire workflow into a centralized digital platform, allowing employees, managers, procurement teams, vendors, and administrators to interact through dedicated dashboards.

The system follows an end-to-end procurement workflow:

Purchase Request → Manager Approval → Procurement Processing → Purchase Order → Vendor Fulfillment → Order Completion

It also introduces automation features such as manager availability checking, automatic escalation, approval/rejection undo, request tracking, analytics, and role-based access control.

🎯 Objective

The main objective of the system is to make organizational procurement:

Faster by reducing manual approval delays
Transparent through real-time request and order tracking
Controlled through role-based authorization
Automated through workflow-based processing
Scalable for enterprise-level procurement operations
Data-driven through dashboards, analytics, and reports

⭐ Key Features
👨‍💼 1. Employee Purchase Requests

Employees can create and manage their procurement requests by providing:

Item / request title
Description
Quantity
Category
Amount
Priority
Required procurement details

The system also restricts employees to a maximum number of active requests to prevent unnecessary request accumulation.

👔 2. Manager Approval Workflow

Managers receive purchase requests assigned to them and can:

Review request details
Approve requests
Reject requests
Add remarks
Track pending requests
View approval status

Once approved, the request automatically moves to the Procurement stage.

🔄 3. Approval Decision Undo

The system provides an Undo Decision mechanism for managers.

If a manager accidentally approves or rejects a request, the decision can be reverted within a predefined time window.

This prevents accidental decisions from becoming immediately permanent.

⏱️ 4. Automatic Manager Escalation

One of the important automation features is manager availability-based escalation.

If the assigned manager is unavailable:

The system detects the manager's unavailable status.
An escalation timer starts.
The system continuously monitors the request.
After the configured escalation period, an available Senior Manager is identified.
The request is automatically reassigned.
The workflow continues without remaining blocked.

This helps prevent procurement requests from becoming stuck because of manager unavailability.

🛒 5. Procurement Dashboard

The procurement team gets a centralized dashboard to monitor requests across different stages:

Pending Procurement
Procurement In Progress
Completed Requests

Procurement users can start processing approved requests and update their progress.

📦 6. Purchase Order & Procurement Tracking

The system provides visibility into the procurement lifecycle, allowing users to track where a request currently stands.

The workflow can progress through stages such as:

Pending Manager → Pending Procurement → Procurement In Progress → Completed

This gives employees and procurement teams better visibility into the status of their requests.

🏪 7. Vendor Management

The system provides vendor-related functionality for managing procurement fulfillment.

Vendors can view their assigned/completed orders and update the relevant order information, helping maintain a connection between the organization's procurement team and external suppliers.

📊 8. Admin Analytics Dashboard

Administrators can monitor procurement activities through analytics and dashboard views.

The analytics provide visibility into areas such as:

Procurement activity
Request trends
Approval activity
Vendor activity
Procurement performance
Overall workflow status

This enables management to make decisions based on procurement data rather than manual tracking.

🔐 9. Role-Based Access Control

Different users receive different permissions based on their roles.

Role	Main Responsibility
👨‍💻 Employee	Create and track purchase requests
👔 Manager	Review and approve/reject requests
🧑‍💼 Senior Manager	Handle escalated approvals
🛒 Procurement	Process approved requests and track procurement
🏪 Vendor	Manage assigned/completed orders
🛡️ Admin	Manage users, vendors, analytics and system operations

This ensures that users can access only the functionality relevant to their responsibilities.
